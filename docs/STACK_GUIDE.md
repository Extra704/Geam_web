# 技术栈使用指南

这份指南说明本项目里 `Vue 3`、`Element Plus`、`Spring Boot`、`MySQL`、`JWT`、`Docker` 的使用方式，以及开发时最容易踩坑的地方。

## 1. Vue 3

### 在项目中的作用

- 页面渲染
- 路由切换
- 表单交互
- 游戏界面逻辑
- 与后端 API 通信

### 在哪里使用

- `frontend/src/views/`
- `frontend/src/components/`
- `frontend/src/router/`
- `frontend/src/store/`

### 推荐使用方式

- 页面放在 `views`
- 可复用组件放在 `components`
- 接口请求统一放在 `src/api`
- token 工具统一放在 `src/utils/auth.js`
- 单页独有的游戏状态优先放在页面内部

### 注意事项

- Vue 3 不要再搭配 `Element UI`
- 路由写法与 Vue 2 的 Router 3 不同，这里用的是 `Vue Router 4`
- 应用入口不再使用 `new Vue()`，而是 `createApp()`
- 不要在组件里到处直接写请求地址，统一从 `request.js` 管理

## 2. Element Plus

### 为什么不是 Element UI

这是最关键的一点：

- `Element UI` 主要面向 `Vue 2`
- `Element Plus` 才是 `Vue 3` 对应组件库

所以如果你要保留 `Vue 3`，就应该使用：

`Element Plus`

### 在项目中的作用

- 登录注册表单
- 排行榜表格
- 游戏卡片
- 弹窗
- 按钮
- 菜单导航
- 提示消息

### 推荐使用方式

- 登录和注册用 `el-form`
- 排行榜和后台列表用 `el-table`
- 首页游戏入口用 `el-card`
- 操作提示用 `ElMessage`

### 注意事项

- Vue 3 项目里不要安装 `element-ui`
- 样式建议保持统一，不要混用太多第三方 UI 风格
- 如果后期优化性能，可以改成按需引入

## 3. Spring Boot

### 在项目中的作用

- 提供 RESTful API
- 登录鉴权
- 业务逻辑处理
- 数据库访问组织
- 安全配置管理

### 当前分层结构

- `controller`：接收请求、返回响应
- `service`：业务逻辑
- `mapper`：数据库访问
- `entity`：数据库实体
- `dto`：请求参数对象
- `vo`：响应对象
- `security`：JWT 与安全过滤器

### 推荐使用方式

- Controller 尽量轻，只做参数接收和返回
- 业务规则放到 Service
- 响应格式统一封装
- JWT 和安全配置独立放在 `security`、`config`

### 注意事项

- 不要把密码返回给前端
- 注册和登录要做参数校验
- 异常处理尽量集中管理
- 生产环境不要把密钥直接写死在代码里

## 4. MySQL

### 在项目中的作用

- 存用户信息
- 存游戏信息
- 存游戏记录
- 存排行依据

### 推荐使用方式

- 数据库字符集使用 `utf8mb4`
- 排行查询字段要考虑加索引
- 密码只保存加密后的哈希值
- 历史记录表和排行榜逻辑可以分开考虑

### 注意事项

- 绝对不要明文存密码
- 排行榜查询如果数据大了，需要优化 SQL
- 表结构命名尽量清晰统一
- 如果后续加任务、关卡、道具，建议单独扩表

## 5. JWT

### 在项目中的作用

- 无状态登录认证
- 保护用户相关接口
- 保护成绩提交接口
- 保护后台接口

### 典型流程

1. 用户登录
2. 后端校验用户名和密码
3. 后端签发 JWT
4. 前端保存 token
5. 前端请求头携带 `Authorization: Bearer <token>`
6. 后端过滤器解析 token 并识别用户

### 推荐使用方式

- 设置合理过期时间
- 在过滤器中统一解析 token
- token 内保存用户 id、用户名、角色
- 管理员接口建议做角色区分

### 注意事项

- 前端退出登录本质上通常是删除本地 token
- token 过期后前端要有跳转登录逻辑
- `Bearer ` 前缀要保持一致
- JWT secret 在生产环境必须安全管理

## 6. Docker

### 在项目中的作用

- 一键拉起前后端和数据库
- 保证不同机器部署环境一致
- 方便课程项目展示和交付

### 当前容器结构

- `mysql`
- `backend`
- `frontend`

### 推荐使用方式

- 后端数据库配置通过环境变量传入
- 前端打包后由 Nginx 托管
- 本地联调或演示时用 `docker compose up --build`

### 注意事项

- MySQL 启动速度可能慢于后端，真实项目要考虑服务就绪问题
- 不要把生产环境密钥直接提交到仓库
- 端口不要暴露过多
- 前后端分离部署时要确认跨域配置

## 7. 这套项目怎么开发最顺

1. 先跑通后端注册和登录接口
2. 再接前端登录页和注册页
3. 做一个最小可运行小游戏
4. 接入成绩提交
5. 做排行榜页
6. 最后做 Docker 部署
